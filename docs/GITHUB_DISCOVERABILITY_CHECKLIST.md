# GitHub discoverability checklist for LTP

This checklist is focused on increasing organic discovery, star conversion, and trust from first-time visitors.

## 1) Sharpen the repository first impression

- [ ] Keep the README hero section focused on a single sentence value proposition.
- [ ] Keep 3–4 trust badges only (protocol version, conformance schema, security posture, license).
- [ ] Add a short “Why watch this repo” block in top fold.
- [ ] Keep one explicit CTA for each primary audience (agents, fintech/compliance, devtools).

## 2) Improve search and topic relevance

- [ ] Add and maintain GitHub topics (suggested):
  - `ai-agents`
  - `protocol`
  - `deterministic-systems`
  - `auditability`
  - `fintech-infrastructure`
  - `compliance`
  - `security`
  - `developer-tools`
- [ ] Ensure README includes exact high-intent phrases users search for:
  - “verifiable AI agent handoffs”
  - “deterministic replay for AI systems”
  - “audit trail for AI agents”
  - “AI continuity protocol”

## 3) Raise conversion from visitor to contributor

- [ ] Pin “Start here” in three links maximum: spec, quickstart, conformance report schema.
- [ ] Keep CONTRIBUTING and GOVERNANCE clearly linked near the top of README.
- [ ] Maintain issue labels for onboarding (`good first issue`, `docs`, `help wanted`).
- [ ] Keep at least 3 open, beginner-friendly issues with concrete acceptance criteria.

## 4) Build trust with proof, not claims

- [ ] Keep one canonical sample trace and a one-command verification path.
- [ ] Surface reproducible CI artifacts in every release note.
- [ ] Publish a monthly conformance snapshot (what changed, what is stable).
- [ ] Add short architecture diagram in README or link within top section.

## 5) Improve release visibility

- [ ] Publish GitHub Releases with concise operator-facing changelogs.
- [ ] Use release titles with outcome language, not internal names.
- [ ] Keep a “What this unlocks” section for each release.
- [ ] Cross-link release notes to updated docs and example traces.

## 6) Build narrative consistency across docs

- [ ] Keep one canonical market narrative and link all variants back to it.
- [ ] Avoid competing taglines; use one primary message repo-wide.
- [ ] Ensure quickstarts map directly to target personas.
- [ ] Add “When to use / when not to use LTP” near top-level docs.

## Suggested north-star metrics

Track these monthly:

1. README-to-star conversion rate.
2. README outbound click-through to quickstarts/spec.
3. Visitor-to-open-issue conversion.
4. Release note views and referral traffic.
5. Clone-to-return-visitor ratio.

## Suggested 30-day execution order

1. README top fold + CTA cleanup.
2. GitHub topics + pinned onboarding issues.
3. Release template with “What this unlocks”.
4. Monthly conformance snapshot cadence.
